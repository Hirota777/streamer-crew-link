# Streamer crew link v1.0.3

Among Usの色・名前・生存状態をOBSに表示する、Windows向けの非公式配信補助ツールです。通常版・Nebula・SNRに対応し、Discordなしでもクルー画像とゲーム内の名前を表示できます。

## ダウンロード

[最新リリース v1.0.3](https://github.com/Hirota777/streamer-crew-link/releases/tag/v1.0.3)から、通常は `Streamer-crew-link-1.0.3-Windows-x64.msi` を取得してください。Windows 10以降の64ビット版向けです。Node.jsや.NETの別途インストールは不要です。

インストール前に旧アプリを終了してください。同じWindowsユーザーの `%LOCALAPPDATA%\Programs\Streamer crew link` にインストールし、デスクトップとスタートメニューへショートカットを作ります。同じユーザーの既存設定・認証は引き継ぎます。旧ZIP版とMSI版を同時起動しないでください。

ZIP版は `Streamer-crew-link-1.0.3-Windows-x64.zip` を全体展開して使用します。GitHubの「Source code」ZIPは実行用ではありません。各SHA256ファイルで配布物を照合できます。MSI・アプリは未署名です。アンインストール後も設定・認証は残す構成です。完全削除はアプリの保存データ削除機能をご利用ください。

## Discord連携について

Discord連携は一般公開承認済みです（2026年11月12日、提供者確認）。テスター登録は不要です。Discordデスクトップ版を起動し、ご自身のアカウントで連携を許可してください。「Among Usのみ」モードではDiscordなしで利用できます。別PC・別アカウントでの初回接続など、実機確認の状況は「対応範囲と確認状況」を参照してください。

## Discordを使わずに表示する

「配信画面」の表示モードを「Among Usのみ（Discord不要）」にして「変更を保存」を押します。ゲームのロビーに参加すると、クルー画像とゲーム内の名前を自動表示します。メンバーの対応づけは不要です。OBSのURLは共通です。通常版・Nebula・SNRの色と確定済みの死亡表示、縦横・サイズ・名前位置の設定に対応します。発言検出・発言アニメーション・Discord画像は使いません。クルー画像は常に表示します。

モードはプリセットに保存され、元のDiscord対応づけは維持します。Discord連携に戻す場合は表示モードを戻し、必要に応じて接続画面から接続してください。旧設定はこれまでどおりDiscord連携で開きます。ゲームのみの設定で起動した場合は、保存認証があってもDiscordへ自動接続しません。

## Discord連携で使い始める

1. MSIでインストールしたショートカットから起動します。ZIP版の場合は全体を展開し、`Streamer crew link.exe` を起動します。
2. Discordデスクトップ版を起動し、サーバーの通話へ参加します。
3. アプリの「接続」で「Discordと連携・許可」を押します。ブラウザーで自分のDiscordアカウントと表示されたアプリ名を確認して許可してください。
4. Among Usを起動してロビーに参加します。Nebula・SNRを使う場合も、ゲームフォルダーにこのツールのファイルを追加する必要はありません。
5. 「メンバー」でゲーム内の名前とDiscordの参加者を対応づけ、画面下の「変更を保存」を押します。

Windows x64向けです。Node.jsや.NETを利用者が別途インストールする必要はありません。Application ID・Client Secret・Redirect URIの入力も不要です。

認証の保存を有効にすると、次回は自動接続します。Discordが後から起動する場合も待機します。許可を取り消した場合や認証が無効になった場合は、もう一度連携してください。

対応づけを解除する場合は「メンバー」の「解除」を押します。不在メンバーは行が消え、ゲームにいる人は未設定へ戻ります。「変更を保存」で確定し、「変更を元に戻す」で取り消せます。ゲーム内の名前を変更した場合は再設定が必要です。同名の参加者が複数いる場合は取り違えを避けるため該当者を表示しません。

## OBSに表示する

「配信画面」の「URLをコピー」を押し、OBSのブラウザーソースに設定します。

- URL：`http://127.0.0.1:37891/overlay`
- サイズの目安：横並びは1920 × 300、縦並びは360 × 1080
- 背景：透明。アプリが動作している間に利用できます。

プリセットはタブ上部で共通です。メンバーの対応づけと見た目をまとめて保存します。

「見た目を調整」では、縦横の配置、各アイコン・状態マーク・文字のサイズ、間隔、名前の位置、キャラ色の背景、クルー表示のON／OFF、発言中のアニメーションを変更できます。アニメーションは初期値OFF、クルー表示は初期値ONです。Windows側で動きを減らす設定がある場合はアニメーションを抑制します。

調整はプレビューへ即時反映されます。「変更を保存」でOBSと次回起動へ反映し、「変更を元に戻す」で未保存の変更を取り消します。表示人数や配置に合わせてOBS側の幅・高さも調整してください。OBSのサイズを自動変更する機能はありません。

デモは架空の11人で、OBSにもDEMOと表示します。デモ中も見た目を保存でき、実際のメンバーの対応づけは維持します。未保存の変更は保存または取り消してからデモ／本番を切り替えてください。本番では「実際の接続に戻る」を押します。

## ゲーム状態の表示

死亡・追放は白縁の赤い×に統一しています。会議の境界で生死を更新し、通常プレイ中の新しい死亡は次の会議境界まで表示しません。NebulaではMOD側の会議終了記録を使い、追放・追加犠牲者の処理完了に合わせて再同期します。取得失敗は接続状態に同期エラーとして表示します。途中起動時は次の会議から同期します。

0.9.6以降では、読取途切れは最大10秒、終了からロビーへの移行中は最大60秒、表示用情報を一時保持します。明示的なゲーム退出・Discord退出・非表示・対応解除は反映します。この対策は現行の配布版に含まれます。

## 保存・更新・終了

設定・対応づけ・プリセットは `%APPDATA%\Streamer crew link` の `settings.bin` にWindowsで暗号化して保存します。認証もWindowsで暗号化して保存し、配布フォルダーやZIPには入れません。

更新時はアプリを終了し、新しい配布ZIPを別フォルダーへ展開して起動してください。同じWindowsアカウントでは保存済みの設定・認証を引き継ぎます。旧版の使用中フォルダーやAppDataからファイルを新しい配布物へコピーする必要はありません。

「今回は切断」は今回の自動再接続を止め、「保存した認証を削除」はこのPCの保存認証を削除します。設定と認証を初期化する場合は「接続」→「保存データの削除」を使用します。Discord側の許可取消しは別の操作です。

ウィンドウを閉じるとアプリ・読取処理・OBS表示が終了します。

## 対応範囲と確認状況

Windows x64、Discordデスクトップ版、対応表に一致するAmong Usが必要です。ゲーム・MODの対応バージョンは「接続」の「対応バージョンについて」で確認してください。

ゲームを外側から読み取り、ファイル追加・コード注入・メモリー書き込みは行いません。指定のemojis素材36枚（通常18色の生存・Dead）を同梱し、Nebulaの動的色とSNR 3.3.0.0の追加色は素材の色部分を取得RGBへ置き換えます。輪郭・骨・ハイライト・透明部分は保持します。SNR・Nebulaの同時導入は対象外です。

記録上、Nebulaの実プロセスからの色・会議終了件数、SNR 3.3.0.0の単独ロビーからの色・会議管理情報の取得を確認しています。0.9.3では自動テスト50件、以降は対応解除・表示設定・ロビー移行時の表示保持などのブラウザー検証を記録しています。これらは複数人の実ゲームでの検証完了を意味しません。

別PC・別アカウントでの初回認証、実際の複数参加者による会議・追放・ロビー復帰、長時間配信は引き続き確認が必要です。ゲーム・MODの更新や異なる端末との同時参加の可否はゲーム本体側の対応に依存します。

## 認証できないとき

Discordデスクトップ版を起動し、ご自身のアカウントで連携を許可し直してください。一般公開承認済みのため、テスター登録・招待受諾は不要です。`invalid_scope` や `unauthorized_client` が続く場合は、接続画面のエラーコードを添えてサポート窓口へ連絡してください。認証トークンやパスワードは送らないでください。

ポート37891が他のアプリで使用されている場合は、使用中のアプリを確認してください。

データの扱いは[PRIVACY.md](PRIVACY.md)、利用条件は[TERMS.md](TERMS.md)、配布手順は[DISTRIBUTION.md](DISTRIBUTION.md)、運用・削除対応は[OPERATIONS.md](OPERATIONS.md)、開発手順は[DEVELOPMENT.md](DEVELOPMENT.md)をご覧ください。

このツールはInnersloth、Discord、Nebulaの公式製品ではなく、これらの提供者による推奨・後援を受けたものではありません。

## 0.8.0の変更
以前の素材PNGを廃止し、新規SVGの生存・Deadキャラクターに置き換えました。Discord画像の右下に、死亡は赤い×（C案の白縁）、投票追放は縄（D案のねじり模様＋白縁）を重ねます。シェリフ射殺・誤射・原因不明も共通の死亡表示です。

死亡表示は会議開始時と会議終了時に更新し、追放は投票対象者の死亡確認後に反映します。会議外では直前の表示を維持し、ロビーへ戻るとリセットします。途中起動時は次の会議から同期します。会議の進行を確認できない場合は状態の更新を保留します。通常の役職・殺害者の表示は行いません。0.9.7以降はMADMATE巻き添えの遅延反映に必要な限定的な照合を読取処理内で行います（PRIVACY.md参照）。

「見た目を調整」で縦／横並び、Discord画像の大きさ、キャラクター倍率、状態マークの大きさ、マーク表示の有無を保存できます。縦並びは「キャラクター・Discord画像・名前」を横1行にし、その行を上から下へ並べます。「実寸で確認」はプレビューの表示倍率だけを変更します。デモ中も見た目の調整を保存できます。デモ用メンバーは保存せず、実際の対応づけを維持します。

Node自動テスト43件、会議前後・追放の遅延確定・スキップ・追放回避・試合リセットの読取ロジック、画面上の縦横・サイズ調整と保存を確認しています。実際の複数参加者での会議・追放は未確認です。

## アプリの更新（1.0.1以降）

起動後にGitHubの新しい正式リリースを確認し、「更新する」「あとで」「このバージョンをスキップ」を選べます。「接続」→「アプリの更新」、またはメニューの「更新を確認」から手動確認できます。自動確認の設定はプリセットとは別にこのPCへ保存します。通信できない場合もアプリの起動・配信を続けます。

MSI版では、更新を許可するとWindows x64向けMSIをダウンロードし、GitHubのSHA256とサイズを照合します。「終了して更新」でアプリを終了してインストーラーを開き、正常終了後に再起動します。更新中はOBS表示が止まります。ゲームとDiscordは終了せず、保存設定・対応づけ・認証を引き継ぎます。未保存の編集や別プリセットに退避した編集がある間は終了を止めます。編集したプリセットへ戻り、保存または取り消してから更新してください。

ZIP版は配布ページからMSI版へ移行してください。v1.00には更新確認機能がないため、1.0.1への初回更新は手動で行います。

更新ファイルは正式なGitHubリポジトリのHTTPS配布元に限定します。SHA256は破損・不一致を検出しますが、コード署名の代わりではありません。MSIとアプリは引き続き未署名です。更新のキャンセル・失敗・再起動要求は区別して案内し、PCを自動で再起動しません。

リリースタグは今後 `v1.0.1` のような３桁のバージョンとし、MSIファイル名の内部バージョンと一致させます。旧タグ `v1.00` は内部バージョン `1.0.0` として認識します。新しい版を検出してもMSIがない・複数ある・サイズやSHA256が取得できない場合はインストールしません。

## 1.0.2の修正

未保存の編集により終了が中止された場合は、内部通信・ゲーム読取・OBS表示を維持します。更新用の保存先が使えない場合もアプリ本体は起動し、更新機能だけに理由を表示します。保存先を修復後、手動の「更新を確認」で再試行できます。

取得済みのMSIは「あとで」やアプリ再起動後にも再利用します。GitHubの最新リリースとバージョン・サイズ・SHA256が一致することと、ファイル本体のハッシュを再確認してから「終了して更新」を表示します。破損・削除・別リリースのファイルは再利用しません。

## 1.0.3の更新起動修正

Windowsで「終了して更新」の準備がタイムアウトする問題を修正しました。補助処理の実起動と、親プロセス終了後の継続を確認しています。v1.0.1・v1.0.2からは一度MSIを手動実行して更新してください。アプリの編集内容を保存して終了し、新しいMSIを起動します。ゲームとDiscordは終了する必要がありません。
