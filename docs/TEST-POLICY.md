# 検証方針

適用日：2026年11月13日。Streamkit版と公開版後継の準備が対象です。

## 基本ルール

0.3.0で成功した自動テスト151件とWindows確認を基準とします。確認済みの同じ操作を、変更理由なく手動で繰り返しません。自動テストは削除せず、不具合の再発を防ぐため維持します。

変更箇所に対応する自動テストを実行します。保存・状態配信・共通描画など複数機能に影響する変更、依存関係の更新、配布前は全自動テストを実行します。成功後は、新たな変更・失敗・未解決の疑いがなければ同じテストを繰り返しません。文書のみの変更ではアプリのテストやMSIの再作成は不要です。

## 原則として自動テストで維持する項目

| 項目 | 手動で再確認する条件 |
| --- | --- |
| プリセットの名前変更・複製・削除・読み込み・書き出し | 操作画面、保存形式、ネイティブのファイル選択を変更したとき |
| メンバー／見た目の保存先分離 | 保存先やプリセット切替の仕様を変更したとき |
| 未保存編集の保護、遅い応答の順序制御 | 画面の状態管理や通信処理を変更したとき |
| 設定の暗号化保存・全削除と旧バックアップの限定清掃 | 保存形式、暗号化、ファイル操作を変更したとき |
| デモ情報と配信表示の分離 | デモ、イベント配信、OBS出力を変更したとき |
| 入力検証、不正な接続元からの変更拒否 | API、権限、通信境界を変更したとき |

Windowsでの暗号化、再起動後の設定保持、ネイティブ書き出しは確認済みです。保存方式・Electron・梱包・インストール先を変えた場合に手動で再確認します。自動テストの失敗、利用者からの再発報告、実環境だけの差が疑われる場合も手動確認を再開します。

## 優先して残す実環境の確認

以下は未完了です。自動テストの成功を、実機確認済みとは扱いません。

| 優先度 | 確認内容 | 合格条件 |
| --- | --- | --- |
| 1 | 実ゲーム＋複数人のDiscord通話＋OBSを通した表示 | 入退室・発言・対応づけ・表示順が正しく、デモを切り替えても配信へ混ざらない |
| 2 | 通常版・Nebula・SNRの会議と死亡更新 | 通常死亡は会議開始、追放は会議終了後、NebulaのMADMATE巻き添えとSNRの道連れ・後追いは次の会議開始に反映する。ロビー復帰時に不要な表示消失がない |
| 3 | v1.1.0の初回起動と旧設定削除 | 初回案内に同意後、既知の旧設定を削除して開始し、新しい設定は次回起動で維持する。旧設定の互換性は利用者指示により対象外 |

環境・Among Us本体とMODのバージョン・対象アプリ版・期待する表示・実際の結果を記録します。参加者が必要な確認を1人のテストで合格にしません。実行のためにゲームフォルダーを変更したり、利用者のゲーム・Discordを終了したりしません。

## 記録

確認済みの基準は [0.3.0検証記録](WORKSPACE-030-VALIDATION.md) と [OBS確認記録](OBS-VALIDATION.md) を参照します。未実施は未実施のまま残し、手動確認を省く判断と混同しません。
