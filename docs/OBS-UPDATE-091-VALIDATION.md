# 0.9.1 OBS更新時のちらつき抑制

## 原因と限界

利用者からOBSの配信表示で発生していると確認。公式obs-browserのUpdate実装では、カスタムCSSが変わるとDestroyBrowser/DestroyTexturesを実行する。現在のCSS連携方式で実際のCSS変更時の再表示を完全に除去するものではない。公式Streamkitのページから内部データを取得したり、セキュリティ設定を無効化したりはしない。

根拠：https://github.com/obsproject/obs-browser/blob/master/obs-browser-source.cpp の BrowserSource::Update（確認日2026年11月15日）。

## 対策

- 同じURL内の描画変更は750msの待機で集約、連続変更にも1800msの上限を設定。描画に無関係なゲーム名・stable・プリセット名等で予約を先延ばしにしない。元の表示へ戻った予約は破棄する。
- 停止・URL削除・表示先変更は即時処理。未変更の出力ファイルは再書込しない。
- OBSのLuaは、同じ設定のscript_updateで元ページへの復元とStreamkit再設定を繰り返さない。実際に変わったソース属性だけ更新する。初期化・復元中や手動編集で一時停止した状態は省略しない。
- アプリの見本の差分更新は今回の対象外。利用者の回答に合わせOBS連携側を修正。

## 検証

単体149件・画面43件、計192件成功。追加4件で、連続更新の集約、描画に無関係な更新による延期の防止、最大待機時間、停止・URL解除・切替、予約取り消しを確認。実際の350ms間隔の自動保存4回を最後の1回だけ出力するテストも成功。

OBS同梱LuaJITを使う既存テストへ、同一設定の再適用を省くこととCSSだけ変更した際にURLやサイズを再適用しないことを追加。同期・復元・タイムアウト・OBS起動時の保留復元・参照解放のテストも成功。

既存UIテストの350ms固定待機は、連携ファイルの実反映を待って確認する形へ変更。

利用者のOBS・ゲーム・Discord・起動中アプリは操作していない。実際のDiscord画像を使ったOBSのちらつきの比較は未実施。更新後にアプリのOBS連携を開始し、OBSでLuaスクリプトを一度再読み込みする必要がある。
