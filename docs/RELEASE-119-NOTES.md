# Streamer crew link v1.1.9

## OBS停止通知と表示ファイルの検証

- 通常の状態ファイルが書き込みできなくても、独立した停止通知ファイルでOBSに停止を伝えます。
- 両方とも書けない場合、アプリの実行中は停止通知を2秒ごとに再送します。停止通知の再送で配信を再開することはありません。
- 明示的な再開では待機中の停止再送を取り消し、独立した停止通知を削除してから連携を開始します。
- 正常終了時にも両方の通知が書けない場合は、OBSで同期を手動停止する案内を出します。書き込みできないまま停止通知の成功として扱いません。
- 表示ファイルを最後に生成した内容と照合し、破損・不正なCSS・リビジョン不一致・過大なファイルも検出して自動復旧へ移行します。

更新後、アプリを起動し、OBSの「ツール → スクリプト」で `streamer-crew-link.lua` を再読み込みしてください。独立した停止通知を読む処理はOBS側にも必要です。

配信エラー時に最後の正常な設定を保持する動作、自動復旧の間隔、意図的な一時停止、既存設定の保存方式は維持しています。

## 検証

内部テスト193件・画面テスト49件、計242件が成功しました。停止通知の別経路送信、両経路失敗時の再送、明示再開での再送取り消し、正常終了時の案内、JSON破損・CSS改変・リビジョン不一致・過大ファイルの検出と再生成を確認しました。OBS同梱Luaで独立した停止通知の優先と明示再開までの停止維持を検証しています。実通話・複数人の実ゲームは未検証です。
