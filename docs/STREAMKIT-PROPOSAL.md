# Streamkit連携 検討仕様

作成日：2026年11月13日／状態：0.2.0でURL管理・ID対応づけ・OBSのCSS/Lua同期を実装。実通話の一連の確認は未完了。

現在の操作と制約は[README](../README.md)を参照。以下は当初の検討記録。0.2.0では手動のID登録とOBSカスタムCSSを採用し、公式表示からデータを抽出する方式は採用していない。根拠：[OBSブラウザーソース](https://obsproject.com/kb/browser-source)、[OBSスクリプト](https://docs.obsproject.com/scripting)、[Discord開発者ポリシー](https://support-dev.discord.com/hc/en-us/articles/8563934450327-Discord-Developer-Policy)。

## 目的

利用者が公式StreamkitのVoiceウィジェットで生成した表示用URLを初回に貼り付け、プリセットに保存する。以降は保存済みURLを再利用する。公開版のRPC権限を使う方式から独立した、非公開プロジェクトで検討する。

公式の根拠：[DiscordのOBS Streamkit案内](https://support.discord.com/hc/en-us/articles/223415707-Using-Discord-s-OBS-Streamkit-Overlay)。公式手順では利用者による許可、サーバー選択、表示調整、生成URLのOBSブラウザーソースへの貼り付けが案内されている。

## 初回の操作

1. 接続画面で「公式Streamkitを開く」を選ぶ。
2. 利用者が公式画面で必要な許可を行い、Voice・サーバー・通話チャンネルを選択する。
3. 公式画面で生成されたVoice表示用URLをアプリの入力欄に貼り付ける。手入力も可能だが、コピー・貼り付けを推奨する。
4. URLを検証する。未保存であることを表示し、「メンバーを保存」で選択中のメンバープリセットへ保存する。
5. 「Streamkit URLをコピー」からOBSの別ブラウザーソースへ設定し、表示を確認する。

公式設定ページそのもののURL、Chat/Statusウィジェット、認証途中のURLは保存対象にしない。具体的なVoice表示URLのパス・パラメーター形式は公式画面で実機確認してから固定する。

## プリセットの役割

| 種類 | 保存するもの |
| --- | --- |
| メンバープリセット | Streamkit表示用URL、ゲーム側との対応づけ、配信用の名前、表示対象、並び順 |
| 配信画面プリセット | 自作表示部分の縦横・サイズ・背景・名前位置・状態表示、合成位置や倍率（統合方式が成立する場合） |

URLは対象サーバー・通話先に紐づくためメンバープリセットへ保存する。配信画面プリセットの切替ではURL・対応づけを変更しない。メンバープリセット切替では保存済みURLを読み出すが、見た目の設定は維持する。

StreamkitがURL側で持つ文字色・画像表示等の設定は、その公式画面で調整する。自作アプリの表示設定が、別オリジンの公式ウィジェット内部にも適用されるとは扱わない。

## 保存・再利用

- URLもアプリの設定と同様にWindowsで暗号化して保存する。
- 入力中の変更は自動確定しない。保存成功後に「保存済み」にする。
- 再起動後は選択中のメンバー用・配信画面用プリセットとURLを読み出す。
- 未保存URLがある状態で同じ種類のプリセットを切り替える場合は保存・取り消しを案内する。別画面による変更時は未保存編集を退避する。
- サーバーやチャンネルを変えた場合は、公式Streamkitで新しいURLを作り、対象メンバープリセットのURLを更新する。
- 別PCでの利用・Discord側の許可取り消し等では公式Streamkit側の再認証が必要になり得る。「一度保存すれば必ず認証不要」と案内しない。
- 「URLを解除」はそのメンバープリセットのURLだけを空にする。公式側の許可取り消しとは区別する。

## URLの検証と表示状態

- HTTPSかつホスト名が正確に `streamkit.discord.com` と一致するものだけを許可する。似たドメイン、ユーザー名・パスワード付きURL、想定外ポートは拒否する。
- 実機で確認したVoice表示用パスだけを許可する。正規の表示用パラメーターは維持し、URLからアカウントのトークンを収集しない。
- 入力欄の任意URLへサーバーからアクセスしない。公式ページは外部ブラウザーから開く。
- URL全体はログ・クラッシュ報告・共有用の診断出力に含めない。サーバー・通話IDを不必要に公開しない。
- 状態は「未設定」「未保存」「URL保存済み」「表示を確認してください」などとする。保存やページ読込だけで「通話に接続中」と判定しない。
- ネットワーク失敗、認証不足、空の通話を区別できない場合は、原因を断定せず公式表示の確認手順を案内する。

## できることと、まだ確定できないこと

URLの保存・再利用・コピーは実装可能。公式StreamkitをOBSの独立したブラウザーソースへ設定する使い方は公式に案内されている。

一方、Streamkitから参加者一覧・名前・発言状態を自作アプリへ受け渡す公開APIは、今回確認した資料では見つかっていない。URLを入力するだけで既存のDiscord参加者候補一覧や対応づけが自動生成できるとは判断できない。

| 項目 | 現段階の判断 |
| --- | --- |
| 公式Voiceウィジェットの表示 | OBSでの直接表示を利用する方向 |
| 参加者画像・名前・発言表示 | 公式ウィジェット内の表示を利用する方向 |
| URLのプリセット保存・切替・再利用 | 実装対象として定義可能 |
| 自作アプリ内への埋め込み | 公式側の埋め込み制限・認証・OBS環境を検証して判断 |
| Discord参加者の候補をアプリに自動表示 | 未確定。公開APIの存在を確認できていない |
| クルーの色・生死と画像を1人ずつ重ねる | 未確定。本人の特定と表示位置の維持が必要 |
| 入退室・表示順変更後も対応がずれない | 統合方式の採否を決める必須検証 |
| 既存と同じ横表示・名前位置・発言アニメーション | 未確定。公式ウィジェットの表示仕様に左右される |

公式ウィジェットを枠として表示できても、その内部情報の取得や自在な加工が可能とは限らない。ブラウザーの同一オリジン制限を無効化する方式、公式StreamkitのアプリID・認証の流用、Discordユーザートークンによる自動化を前提にしない。

## 開発の順序と完了条件

### 1. 非公開プロジェクトの実行環境を分離する

アプリ名、設定保存先、待受ポート、更新先を公開版と分離する。公開版の設定を自動移行・初期化しない。検討用アプリを公開版の自動更新先にしない。これらを行うまでは基点コードをそのまま実行しない。

### 2. URL保存機能を試作する

公式ページへの案内、URL入力・検証、メンバープリセット保存、再起動後の復元、コピー、URLだけの解除を実装する。配信画面プリセットとの独立動作を確認する。

これはURL管理機能の完了条件であり、現在のDiscord連携機能を置き換えたという意味ではない。

### 3. 表示統合の実現性を確認する

実際の公式表示用URLで次を確認する。認証操作は利用者本人が行う。

- OBSで公式表示が出ることと、アプリ再起動・Discord再起動後の挙動。
- アプリへの埋め込み可否と、認証環境の違い。
- 参加者の入退室、再接続、同名、名前変更、発言中のみ表示の設定、人数増減。
- 縦横・拡大縮小・名前表示の条件で、クルーとDiscord画像の対応がずれないか。
- 会議前後の生死更新と、ロビー復帰時の表示保持。

参加者との対応を安定して保てない場合、完全統合は採用せず、公式Streamkitと自作クルー表示を別ソースで併用する案へ戻す。別ソースの併用でも、自動的に各人の画像へ正しいクルーが重なるとは案内しない。
